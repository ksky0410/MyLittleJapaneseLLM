# 実験030：約20M parameterモデルへの拡張

## 開始前の計画

実施日時は2026-09-05、担当者はCodexです。実験029では、FineWeb2 Edu Japaneseを含む約5M Tokenの混合コーパスを5M級モデルへ2,500 step学習し、general validation loss 5.2905、FineWeb test loss 4.5607まで改善しました。一方、固定chat testは定型的な短文が中心で、自然な文脈応答には至っていません。モデル容量が約5.2M parametersに制限されていることが、複数domainの保持と文脈条件付けを妨げている可能性があります。

今回の仮説は、Tokenizer、学習データ、seed、optimizer、学習率schedule、batch size、context lengthを固定し、モデルを約5.2Mから約19.4M parametersへ拡張すると、同じ2,500 stepでもgeneral・FineWeb・会話・医療のvalidation lossと固定chat testが改善するというものです。反対に、モデル容量だけを増やしても学習Token数が少なければ、validation lossは下がらず、生成がより不安定になる可能性があります。

主モデルはvocab size 4,096、dim 384、10層、6 heads、context length 256、MLP倍率4、absolute position embeddingです。現在の実装で概算約19.4M parametersとなり、5Mモデルの約3.7倍です。まず100 stepのsmokeを別出力先で実行し、shape error、NaN、メモリ不足、速度を確認します。smokeの学習率schedule horizonは100 stepであり、性能比較には使いません。本学習は同じ2,500 step horizonを使い、実験029の最終モデルと比較します。

## 使用するデータとTokenizer

学習Token列は`artifacts/tokens/mixed-ja-token-budget-fineweb2-5m-v1-train.bin`です。Token数は4,999,958、SHA-256は`54eb3fab617c94bda59899db4f78e6ac65665606219414a710e40cc8ccb8603c`です。FineWebの出典、抽出条件、混合source比率は実験028のmanifestとノートへ記録しています。

Tokenizerは`artifacts/tokenizer/mixed-ja-80-10-10-v2-unigram.model`で、SHA-256は`5bde054fb91da54cbf56673a6d25b630399d95ec331049e5fa2af1a8d60731e4`、実語彙数は4,096です。既存general validation、FineWeb test、会話、医療のToken列も実験029と同じものを使います。実験030ではTokenizerを作り直さず、モデル容量だけを変更します。

## モデルと学習条件

本学習は`configs/fineweb2-mixed-ja-20m-2p5k.toml`で固定します。batch size 8、最大2,500 step、evaluation interval 100、sample interval 100、evaluation batches 20、AdamW、learning rate 3e-4、minimum learning rate 3e-5、warmup 300、weight decay 0.1、seed 42です。smokeは同じモデル構造で最大100 step、warmup 50、専用checkpoint・sample保存先を使います。

主比較は実験029の5Mモデルと実験030の20Mモデルです。両方ともFineWeb混合Token列をランダムwindow samplingで学習し、同じ固定chat-test-v1 manifestを使います。評価ではlossだけでなく、EOS到達、生成Token数、Token overlap precision・recall・F1、生成TXTの崩れ方を記録します。意味的な会話品質はToken overlapだけで確定しません。

## 実行前の再現情報

実験029を記録したcommitは`a88b262`です。実験030のconfigとこのノートをcommit・pushしてから、次のsmokeを実行します。

```bash
.venv/bin/python scripts/inspect_model.py --config configs/fineweb2-mixed-ja-20m-smoke.toml
.venv/bin/python scripts/train.py --config configs/fineweb2-mixed-ja-20m-smoke.toml
```

smokeが成功した場合は、同じ条件の本学習を次のコマンドで実行します。

```bash
.venv/bin/python scripts/train.py --config configs/fineweb2-mixed-ja-20m-2p5k.toml
```

成功基準は、smokeと本学習がNaN、shape error、データ長エラー、メモリ不足なしに完走し、metrics、checkpoint metadata、100 step以下の間隔の固定prompt生成文を保存することです。性能面では、実験029のgeneral validation loss 5.2905またはFineWeb test loss 4.5607を下回ることを有望な変化の目安とします。ただし、学習データ量が約5M Tokenに限られるため、モデル容量拡大だけで知識量が増えるとは解釈しません。
