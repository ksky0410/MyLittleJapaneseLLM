## 今回確かめたいこと

通常の日本語文書を主軸にしながら、Issue #1の会話データと医師国家試験データを少量加えた学習用コーパスを、会話の境界と医療データのsplitを壊さずに作成できるかを確認する。医療専用モデルにはせず、一般的な日本語の事前学習に会話・専門語彙を補助的に加える方針である。

仮説は、一般日本語・会話・医療を単位数で80%・10%・10%にすると、一般文書の文体を保ちながら、会話の短い応答や医療用語も学習できるというものである。ただし、現状の一般文書は青空文庫の『吾輩は猫である。』一作品だけで2,146単位しかない。そのため今回は、一般sourceを使い切らずに80%を守れる総2,680単位を上限とする。一般コーパスを増やした場合の効果は別の実験で検証する。

## 入力と再現条件

混合処理のコードは`a26b0df`で固定した。入力は次のtrain splitだけに限定し、validation・test・challengeは混ぜない。

- 一般日本語：`artifacts/corpus/aozora-neko-formal-v2/train.txt`
- 会話：`artifacts/corpus/conversation-v1/train.txt`
- 医療：`artifacts/corpus/medical-qb-v2/train.txt`
- 乱数seed：42
- 重み：一般8.0、会話1.0、医療1.0
- target units：2,680
- 期待する採用単位数：一般2,144、会話268、医療268
- 出力：`artifacts/corpus/mixed-ja-80-10-10-v1.txt`
- manifest：`artifacts/corpus/mixed-ja-80-10-10-v1.manifest.json`

一般sourceは1行1段落、医療sourceは1問1行、会話sourceは`<|startofconversation|>`から`<|endofconversation|>`までを一会話として扱う。完全一致する単位はsource指定順で一つだけ残す。出力のSHA-256、入力SHA-256、採用件数、実際の比率、重複除去数はmanifestに保存する。

実行コマンドは次のとおりである。

```bash
.venv/bin/python scripts/mix_corpora.py \
  --source general=artifacts/corpus/aozora-neko-formal-v2/train.txt \
  --source conversation=artifacts/corpus/conversation-v1/train.txt \
  --source medical=artifacts/corpus/medical-qb-v2/train.txt \
  --weight general=8.0 \
  --weight conversation=1.0 \
  --weight medical=1.0 \
  --target-units 2680 \
  --seed 42 \
  --output artifacts/corpus/mixed-ja-80-10-10-v1.txt \
  --manifest artifacts/corpus/mixed-ja-80-10-10-v1.manifest.json
```

## 学習へ進む条件

混合後にmanifestの採用単位数が期待値と一致し、会話のstart/end数が一致し、医療sourceに700回のchallenge問題が含まれないことを確認する。確認に失敗した場合は学習せず、混合処理の実装または入力splitを修正して別途記録する。

条件を満たした場合は、この混合テキストだけでTokenizerを学習し、5Mモデルのsmoke学習を行う。Tokenizerはvalidation・test・challengeから学習しない。学習前に、Tokenizerの語彙数、実際のtoken数、モデル構成、学習率、batch、context、step数をこのノートへ追記する。

## 結果

混合コマンドを実行し、`artifacts/corpus/mixed-ja-80-10-10-v1.manifest.json`へ条件とハッシュを保存した。出力テキストのSHA-256は`8054fd5ea66fda327f79d0b387a53dd8cd91904fb6d7cbfbe3f0c7c517551f32`、出力は2,680単位、12,445行、822,562文字である。

入力は合計19,923単位で、完全一致重複22単位を除いたunique単位は19,901であった。一般source内に17件の重複があったため、一般の採用可能なunique単位は2,129となり、当初の期待2,144より15少なかった。その結果、実際の採用単位数は一般2,129、会話276、医療275であり、比率は一般79.4403%、会話10.2985%、医療10.2612%となった。一般sourceが枯渇した分は会話・医療へ再配分された。これは、単位を複製せずに80/10/10へ近づける現行仕様どおりの結果である。

会話のstart/end markerはそれぞれ276個で一致し、会話途中の分割はなかった。医療の700回問題が混合出力に含まれないことも確認した。入力の各SHA-256と採用件数はmanifestに残した。混合コーパスの本文はサイズが大きいためGit管理対象外だが、再生成コマンドとハッシュはこのノート、条件はmanifestから確認できる。

この結果から、現状の一般sourceは短いsmoke実験には使えるが、長い学習で一般80%を厳密に維持するには不足していると分かった。次はこの出力でTokenizerを学習して小型モデルのsmoke学習へ進み、一般sourceを増やした場合には同じ条件で再び比率と生成品質を比較する。学習を実施した場合は、stepごとの生成文を`artifacts/samples/`へ保存し、悪い出力や途中停止も削除しない。
