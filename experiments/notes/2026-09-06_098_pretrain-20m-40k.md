# 実験098：20M Token混合コーパス・50Mモデル40,000 step事前学習

## 目的

実験080では、FineWeb2 Edu Japanese、Wikipedia、会話、医療などを含む約10M Token列を50Mモデルへ5,000 step提示した。validation lossと簡易chat F1は改善したが、固定promptは空応答へ崩れ、自然な日本語を獲得したとは言えなかった。実験096の監査では、081の主基盤が約10M提示Tokenにとどまり、事前学習不足が有力な仮説として残った。

今回は蒸留や教師LLMを使わず、既存の10M混合列に、同じTokenizerで未使用部分から抽出したFineWeb2日本語約5M TokenとWikipedia日本語約5M Tokenを加え、約20M Tokenの混合列を作る。そのうえで、同じ50M構造をランダム初期値から40,000 step学習し、総提示Tokenを約81.92Mまで増やす。学習量を増やすことで、validation lossだけでなく、自然な短文生成、会話評価、反復やEOSへの崩壊が改善するかを確認する。

## 事前仮説

1. 10M列から20M列へ広げたことで、FineWebとWikipediaの重複しない日本語表現が増え、FineWeb testおよびWikipedia validationのlossが、080の5,000 step条件より下がる。
2. 40,000 stepまで総提示Tokenを増やすと、事前学習直後の「今日はなにをしていましたか？」の空応答が減り、固定promptの平均生成長と文法的な日本語らしさが改善する可能性がある。
3. 会話と医療の比率は20M列で相対的に薄まるため、一般日本語のlossが改善しても会話応答が改善するとは限らない。一般、FineWeb、Wikipedia、会話、医療、RPC、MRMPを分けて評価する。
4. 40,000 stepでvalidationが悪化する場合は、単純なstep延長が過学習または学習率scheduleの問題を起こしたと判断し、途中checkpointを比較対象として残す。

## データ設計

既存10M列は`artifacts/corpus/mixed-ja-token-budget-fineweb2-wikipedia-10m-v1.txt`を使う。追加FineWebは、既存抽出が終了した行の後ろから、同じローカルparquet`data/downloads/fineweb-2-edu-japanese-180ca00/train-00000-of-00283.parquet`の`skip_rows=30,000`以降を最大5M Token抽出する。追加Wikipediaは、既存validationが使ったshard1の先頭部分を避け、`data/downloads/wikimedia-wikipedia-20231101-ja/train-00001-of-00015.parquet`の`skip_rows=1,000`以降を最大5M Token抽出する。元parquet、元のmedilink_analysis、医師国家試験原データは変更しない。

3つのUTF-8 corpusを、既存混合列にweight 2.0、追加FineWebにweight 1.0、追加Wikipediaにweight 1.0を与えて、Tokenizer上限20,000,000 Tokenで重複なく決定的に混ぜる。実際の採用Token数、source比率、入力・出力SHA-256はmix manifestへ保存する。追加データが既存行と完全一致する場合はmix側で除外する。

## 実行予定コマンド

```bash
PYTHONPATH=scripts uv run python scripts/import_fineweb2_edu_japanese.py \
  --input data/downloads/fineweb-2-edu-japanese-180ca00/train-00000-of-00283.parquet \
  --output artifacts/corpus/fineweb2-edu-japanese-v2/next-train.txt \
  --manifest artifacts/corpus/fineweb2-edu-japanese-v2/next-train.manifest.json \
  --skip-rows 30000 --max-tokens 5000000 \
  --tokenizer artifacts/tokenizer/mixed-ja-80-10-10-v2-unigram.model

PYTHONPATH=scripts uv run python scripts/import_wikimedia_wikipedia_ja.py \
  --input data/downloads/wikimedia-wikipedia-20231101-ja/train-00001-of-00015.parquet \
  --output artifacts/corpus/wikimedia-wikipedia-ja-v2/next-train.txt \
  --manifest artifacts/corpus/wikimedia-wikipedia-ja-v2/next-train.manifest.json \
  --skip-rows 1000 --max-tokens 5000000 \
  --tokenizer artifacts/tokenizer/mixed-ja-80-10-10-v2-unigram.model

PYTHONPATH=scripts uv run python scripts/mix_corpora.py \
  --source base=artifacts/corpus/mixed-ja-token-budget-fineweb2-wikipedia-10m-v1.txt \
  --source fineweb_next=artifacts/corpus/fineweb2-edu-japanese-v2/next-train.txt \
  --source wikipedia_next=artifacts/corpus/wikimedia-wikipedia-ja-v2/next-train.txt \
  --weight base=2 --weight fineweb_next=1 --weight wikipedia_next=1 \
  --target-tokens 20000000 --tokenizer artifacts/tokenizer/mixed-ja-80-10-10-v2-unigram.model \
  --seed 9801 \
  --output artifacts/corpus/mixed-ja-token-budget-fineweb2-wikipedia-20m-v1.txt \
  --manifest artifacts/corpus/mixed-ja-token-budget-fineweb2-wikipedia-20m-v1.manifest.json

PYTHONPATH=scripts uv run python scripts/encode_data.py \
  --tokenizer artifacts/tokenizer/mixed-ja-80-10-10-v2-unigram.model \
  --input artifacts/corpus/mixed-ja-token-budget-fineweb2-wikipedia-20m-v1.txt \
  --output artifacts/tokens/mixed-ja-token-budget-fineweb2-wikipedia-20m-v1-train.bin
```

Colabでは、作成したconfigとToken列を含むbundleをアップロードし、`scripts/colab_bootstrap_098.py`で新規T4または利用可能なGPUへ実行する。完了後は`colab_package_098.py`でmetrics、summary、生成文、best checkpoint、ハッシュmanifestを回収する。
