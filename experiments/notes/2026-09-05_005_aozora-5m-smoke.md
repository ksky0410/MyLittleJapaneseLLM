# 実験ノート：青空文庫「吾輩は猫である」5Mモデル予備学習

## 基本情報

- 実験番号：005
- 計画作成日：2026-09-05
- 担当者：ユーザーとCodex
- Gitコミット：`fdd4d38`（青空文庫取り込み、Tokenizer最大長指定、5M設定）
- ブランチ：`main`
- 状態：500 stepの予備学習とcheckpoint再読み込みを完了

今回は、正式な青空文庫コーパスと自作Tokenizerを使って、約5Mパラメータの日本語Decoder-only Transformerが学習可能かを確かめる。いきなり5,000 stepを回さず、500 stepで損失、検証損失、固定promptの生成、checkpointの再読み込みまで確認する。予備学習が正常なら、同じ条件を基に学習を5,000 stepへ延長する。

## 確かめたい仮説

単一作品ではあるものの、約19万tokenの本文を使えば、ランダム初期値のモデルでも日本語の句読点、助詞、文末表現を学習し、初期状態よりvalidation lossと固定promptの出力が改善するはずである。ただし「吾輩は猫である」の文体に強く偏るため、一般的な日本語能力の評価とは解釈しない。

今回の主な失敗条件は、学習開始時にshapeやデータ長のエラーが出ること、lossがNaNになること、validation lossが初期値から下がらないこと、checkpointを再読み込みできないことである。生成文が自然であることは望ましいが、500 stepだけでは成功条件にしない。

## データとTokenizer

- 出所：青空文庫「吾輩は猫である」の公式zip
- 取得URL：https://www.aozora.gr.jp/cards/000148/files/789_ruby_5639.zip
- 元zip SHA-256：`6545750b89ee2c57f215a65079eeab56ee7c997373b7b86e5b00ae74fe69208f`
- 取り込み出力：`artifacts/corpus/aozora-neko-formal-v2.txt`
- 取り込みmanifest：`artifacts/corpus/aozora-neko-formal-v2.manifest.json`
- 分割：seed 42、validation ratio 0.05、学習2,146行、検証113行
- 文字数：学習302,791文字、検証16,530文字
- Tokenizer：SentencePiece Unigram、語彙数4,096
- SentencePiece最大長：20,000 UTF-8 bytes。学習対象の除外を0件にするため、既定値4,192から変更
- 学習Token数：195,717（各行末にEOSを追加）
- 検証Token数：10,771（各行末にEOSを追加）
- 固定サンプルのToken数集計では、EOSを含めない学習本文は193,571 tokenだった

変換後のmanifestでは、注記461件、ルビ9,214件を処理し、本文行の最大文字数を4,000に制限した。取り込み出力には青空文庫の注記、ルビ、作品情報フッターが残っていないことを確認した。単一作品であり、現代の基準では不適切と受け取られる可能性のある表現が含まれる旨も公式カードに記載されているため、生成例を一般的な日本語の代表とは扱わない。

- パラメータ：推定5,197,920

- 実行環境：Apple Silicon MacBook、`.venv`、MLX 0.32.2、Python 3.13.1

## 実行予定コマンド

開始前に、Tokenizer、Token列、設定、Gitの状態が一致していることを確認した。予備学習は設定ファイルの5,000 stepを`--max-steps 500`で一時的に上書きする。

```bash
.venv/bin/python scripts/train.py \
  --config configs/aozora-5m.toml \
  --max-steps 500
```

学習後には、`artifacts/checkpoints/aozora-5m/metrics.jsonl`、`summary.json`、`step_*.npz`とJSON metadata、および`artifacts/samples/aozora-5m/`を確認する。最良checkpointを`generate.py`で再読み込みし、固定promptの出力を別ファイルへ保存する。

## 実験中の記録

学習は指定した500 stepまで停止せずに完走した。step 1、100、200、300、400、500の記録は`artifacts/checkpoints/aozora-5m/metrics.jsonl`へ保存している。validation lossは、step 1の8.756297からstep 100の6.592331、step 200の6.277563、step 300の5.939515、step 400の5.685476、step 500の5.576970へ低下した。perplexityも6,350.6から729.5、532.5、379.8、294.6、264.3へ低下した。train lossは8.779648から5.319933へ低下した。

学習率はwarmupによりstep 1の1e-6からstep 300の3e-4まで上がり、その後cosine decayでstep 500の3.0017e-5まで下がった。step 500時点の経過時間は75.73秒で、summary書き込みまでの経過時間は76.20秒だった。専用の最大メモリ計測は実施していないため、最大メモリは未計測とする。NaN、shape error、データ長エラー、途中停止は発生しなかった。

固定prompt「吾輩は猫である。」の生成結果は、初期の`死ぬ因椎凝台平気でつかない…`という文字崩れから、step 100では短い断片、step 400では「しかしこの方までの上の一羽用するのは、一匹の音がちい。」、step 500では次のように変化した。

```text
吾輩は猫である。ただ主人の生するのはあいで、大きを引き受けてある。これとある。吾輩はこの道が、天道が一本にこの頭にでも、この先は一々をかしにかしに出ない。ところが一としている。この猫だ。彼は五五分かかして、今は二年の中にはいか、またはいで一風のにない。吾輩は今へする。それだからこの方のない。
```

全stepの出力は`artifacts/samples/aozora-5m/`に保存した。step 0、100、200、300、400、500の出力を後から比較できる。step 500のcheckpointを`generate.py`で別プロセスから読み直したところ、次の出力を得た。重みとmetadataの整合性検証、および生成の再実行に成功した。

```text
吾輩は猫である。その二身一疋一四十四年ので見当が心を与しておきを置いて、いくら大分らしまのもこの横に至る。吾輩はその鼻の上で、御取る者の眼が、一時、この横ので、何のかに出じらぬが、一々の名のは、人の御免を切るものばかりに御免しみる。
```

## 結果

学習は成功条件を満たした。lossとvalidation lossが大きく低下し、NaNやshape errorなしに完走し、最良checkpointは最終step 500だった。固定promptにはまだ文法的な崩れや不自然な語の連結が多く残るが、初期のランダムな文字列と比べると、学習コーパスに由来する語彙、句読点、作品固有の文体が現れた。500 stepで自然な日本語を十分に生成できるとは判断しない。

事前の予想は、validation lossと日本語らしい局所的な文のパターンが改善するという点では一致した。一方、単一作品の約19万tokenを約76秒で500 step学習しただけでは、長い文脈や意味の一貫性はまだ得られなかった。これはモデルのパラメータ数だけでなく、学習Token数と学習stepが小さいこと、Tokenizerが4,096語彙であることの影響も含むため、今回の結果だけから原因を一つに決めない。

今回、青空文庫の正式取り込みからToken化、学習、checkpoint保存、再読み込み生成までを一周できた。また、取り込み時の文字数制限とSentencePieceのUTF-8バイト長制限は別物であり、実データでは`--max-sentence-length 20000`を明示しないと41行が除外されることが分かった。修正後はSentencePieceが2,146行すべてを読み込み、Token列にも学習・検証のEOSを含めて保存できた。
