# 実験030：FineWeb混合コーパスでの20M級モデル化

## 開始前の計画

実施日時は2026-09-05、担当者はCodexです。実験028では、約5M TokenのFineWeb混合コーパスを使った5M級モデルが500 stepでは十分に学習できず、実験029では同じ条件でstep数を2,500へ延長しています。実験029の結果を基準として、次にモデル容量だけを増やしたときにvalidation loss、生成文、Issue #1の固定会話評価がどの程度変わるかを確認します。

今回の仮説は、同じデータ・Tokenizer・学習stepで5M級から約20M級へ拡張すると、一般日本語validation lossが下がり、文法崩壊や短い繰り返しが減り、会話testの内容対応も改善するというものです。ただし、学習Token数は約5Mであり、モデルを大きくしてもデータが少なすぎれば過学習または汎化不足になる可能性があります。したがって、lossが下がっても会話能力の向上とは分けて解釈します。

今回はモデル容量以外を変えません。RoPE、RMSNorm、GQA、SwiGLU、KV cache、半精度、学習率変更、データ比率変更は別実験へ分離します。5M級の実験029が2,500 stepまで完了した後、同じFineWeb混合Token列を使って20Mモデルをランダム初期値から学習します。5Mと20Mは同じseed 42で初期化しますが、形状が異なるためcheckpointの重み移植は行いません。

## データとTokenizer

学習Token列は`artifacts/tokens/mixed-ja-token-budget-fineweb2-5m-v1-train.bin`で、4,999,958 Token、SHA-256 `54eb3fab617c94bda59899db4f78e6ac65665606219414a710e40cc8ccb8603c`です。source混合の実測Token比率と入力hashは`artifacts/corpus/mixed-ja-token-budget-fineweb2-5m-v1.manifest.json`にあります。FineWeb test由来validationは`artifacts/tokens/fineweb2-edu-japanese-v1-test.bin`で、2,061,459 Token、SHA-256 `36d8d5c8bc92de1e168b8c3de9dd4ee975dec66f6b644b83bfbf9b239877161c`です。

Tokenizerは`artifacts/tokenizer/mixed-ja-80-10-10-v2-unigram.model`を再利用し、SHA-256 `5bde054fb91da54cbf56673a6d25b630399d95ec331049e5fa2af1a8d60731e4`、vocab size 4,096を固定します。一般・会話・医療のvalidation Token列も実験029と同じものを使い、FineWeb testだけを追加domainとして評価します。Issue #1の会話評価は`experiments/evaluation/chat-test-v1.json`の固定manifestを使い、48例を完全に同じ条件で比較します。

## モデルと学習条件

20M級条件は`configs/fineweb2-mixed-ja-20m-2p5k.toml`に保存します。vocab size 4,096、dim 384、10層、6 heads、context length 256、MLP倍率4、absolute position embeddingで、`scripts/inspect_model.py`の概算は19,382,016 parametersです。実装上のbiasを含む実パラメータ数とは少し差があるため、最終的なmodel signatureと概算値を両方記録します。

batch size 8、最大2,500 step、evaluation interval 100、sample interval 100、evaluation batches 20、AdamW、learning rate 3e-4、minimum learning rate 3e-5、warmup 300、weight decay 0.1、seed 42を使います。5M級実験029と同じスケジュールで、変更は`dim`と`layers`だけです。出力先は`artifacts/checkpoints/fineweb2-mixed-ja-20m-2p5k/`と`artifacts/samples/fineweb2-mixed-ja-20m-2p5k/`へ分け、既存checkpointを上書きしません。

M3 MacBook Air 16GBでは、重みだけでなくAdamWの状態とforward/backward一時領域が必要です。開始前に50〜100 stepのsmokeを行い、checkpoint、step時間、RSSまたは取得可能なメモリ情報、Metalエラーの有無を確認します。smokeが正常なら2,500 step本学習へ進み、危険なメモリ増加やNaNが出た場合は停止して失敗として記録します。batch sizeやcontext lengthを下げる場合は、当初条件から変えた理由と別条件をノートへ追記します。

## 実行前の再現情報

実験029の2,500 step完了commit、または未完了ならその時点の最新commitを記録します。実験029の500 stepまでのmetricsが実験028と一致することを確認し、step scalingの結果を基準としてから20M学習を開始します。学習コマンド、configのhash、Tokenizer・Token列のhash、Python・MLXのバージョンを開始前にこのノートへ追記します。

## 成功・失敗の判断

50〜100 step smokeと2,500 step本学習がNaN、shape error、データ長エラー、Metal初期化エラーなしに完走し、100 stepごとのmetrics・checkpoint metadata・固定prompt生成文が保存されれば実行面は成功とします。一般validation lossまたはFineWeb validation lossが5M級step scaling基準から0.10以上低下することを性能面の有望な目安とします。

固定chat-test-v1ではEOS、平均生成長、Token overlapを保存し、人手レビューtemplateの3項目を自動で埋めません。train本文完全一致候補7例、履歴context超過33例、Token overlapの意味評価限界を明記し、loss改善だけで会話能力を認定しません。

## 実行コマンド

実験029の完了確認後、まず形状確認とsmokeを実施します。

```bash
.venv/bin/python scripts/inspect_model.py --config configs/fineweb2-mixed-ja-20m-2p5k.toml
.venv/bin/python scripts/train.py --config configs/fineweb2-mixed-ja-20m-smoke.toml
```

smokeは`configs/fineweb2-mixed-ja-20m-smoke.toml`で専用checkpointディレクトリへ出すため、本学習出力と混ざりません。smokeが成功した後に次を実行します。

```bash
.venv/bin/python scripts/train.py --config configs/fineweb2-mixed-ja-20m-2p5k.toml
```
